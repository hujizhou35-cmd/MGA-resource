一、我为什么提出这次调整

我对现在的方案有两个核心顾虑：

第一个是分类和检索不够贴近实际绘图。

素材来自很多不同图库，有黑白、灰阶、彩色，也有极简图标、精细线稿、平面插画、半写实和写实插画。即使都画“小鼠”或“肝脏”，它们在图像摘要里的用途也不一样。

我希望黑白与彩色是网站和Agent检索中的重要区分，还希望方便选择极简、精细、写实等大类风格。只按器官、动物、细胞等医学对象分类，不能满足实际选材。

第二个是图像摘要可能越来越趋同。

MGA-Designer 将经常调用这个素材库。如果相似需求总得到同一组前十名，Agent又习惯选择排名靠前的图片，那么即使收集了几千张图，最终反复使用的也可能只有几十张。不同论文的图像摘要会出现相同的小鼠、肝脏、细胞和布局。

我希望素材库的丰富性真正体现在最终选材中，同时保证医学对象正确、图像质量可靠，以及同一张图内部风格协调。

因此，这次调整不是单纯增加几个网页筛选按钮，也不是把搜索结果随机打乱，而是完善“素材描述—检索—候选比较—最终选材—项目记录”这一整条流程。

二、前期分析得出的判断，请据此检查当前实现

此前检查发现，当前目录已经具备文字检索、部分画风关键词和素材家族归并，但尚未形成完整的颜色分类与跨项目选材多样性机制。请以当前代码为准确认哪些已实现，复用已有工作，避免重复建设。

需要特别理解以下区别：

1. 黑白不等于极简，彩色不等于写实。
   一张灰阶解剖图可以很精细；一张彩色图标可以很极简。3D渲染也可能是卡通。写实程度不代表医学准确性。

2. SVG、PNG是格式，不是画风。
   PNG可以是精细医学插画；SVG可以只是黑色符号，也可能内嵌位图。不能从扩展名推断颜色、风格或编辑能力。

3. “同一个对象”“同一件作品的变体”“同一个画风系列”是三种关系。
   两张不同作者画的小鼠，不应仅因对象相同而合并。
   同一作品的SVG、PNG、尺寸和简单配色版本应关联为素材家族。
   不同对象如果属于同一套视觉系列，应能一起检索，便于组成协调的图。

4. 单次搜索多样，不等于跨项目多样。
   MMR等重排可以减少一次结果中的重复，但在目录、查询和参数不变时，仍可能每次返回同样十张图。还需要项目记录和受控轮换。

5. “前十名命中”是检索验收要求，不应变成选材限制。
   算法内部不应只看十个候选；Agent不应自动选第一名。前十个不合适时，应能继续分页、换候选或报告缺口。

6. 同一张GA的协调性与不同GA的差异性要同时满足。
   同一篇里重复表达同一个对象，可以复用相同素材；不同篇之间，在有合适替代品时，应有机会换用其他作品。不能为了多样，把一张GA拼成多种互不协调的画风。

三、可借鉴的现成做法，以及在本项目中的用法

以下是设计参考，不要求部署这些商业服务或采集它们的素材：

- Unsplash把颜色作为独立搜索参数，支持黑白和具体颜色过滤。
  借鉴点：颜色应是可检索的结构化字段，而不只是标题中偶然出现的词。

- Iconify提供SVG颜色解析，并区分可统一着色的图标与固定调色板图标。
  借鉴点：分析当前画面颜色，同时保留是否适合统一改色的信息；不能因为“看起来是单色”就承诺可以任意重着色。

- Icons8 Ouch按表现方式和具体画风系列组织插画。
  借鉴点：既提供极简、写实等大类，又保留可组合的系列关系。

- Algolia的分组去重让同一组变体只占有限搜索位置。
  借鉴点：避免同一作品的不同格式、尺寸和配色占满前十名。

- Elastic/OpenSearch使用MMR，在较大的相关候选集合中兼顾相关性和差异。
  借鉴点：先保证候选合格，再减少重复展示；不为追求差异牺牲医学条件。

- 推荐系统中的探索机制会给较少展示或较少使用的合格候选机会。
  借鉴点：在相关性和质量接近的素材之间进行轮换，避免热门素材不断自我强化。

这些方法可以用现有索引、元数据和轻量重排实现。第一版不预设付费模型、托管搜索服务或向量数据库。

四、颜色和画风分类应该如何实施

1. 分别记录以下维度，字段名可以结合现有schema合理设计：
   - 颜色：黑白、灰阶、彩色、待确认。
   - 调色特点：例如单色着色、少量配色、多色、黑白主体带强调色。
   - 表现方式：线稿、剪影、平面填色、明暗塑形、手绘、3D渲染等。
   - 细节程度：极简、适中、精细。
   - 写实程度：示意、半写实、写实。
   - 明确的作者/画风系列。
   - 标签依据、可信程度、分类版本及复核状态。

   不要求把所有素材强行塞进唯一的画风类别。允许多标签和待确认。

2. 颜色和画风必须落到具体文件或变体。
   比如同一只小鼠有黑白SVG和彩色PNG，家族可以同时具备两种颜色，但搜索“彩色小鼠”时，选中的预览和下载文件必须是彩色版本。

   检索要先判断具体变体是否满足条件，再进行家族归并。避免家族匹配正确、实际返回文件错误。

3. 颜色尽量自动测量。
   优先利用云端已有的原件和预览，分析实际可见区域；SVG可结合结构化颜色解析。考虑透明度、背景、渐变和嵌入位图。

   不要只看整张图平均颜色或简单统计颜色字符串。大片白底会稀释彩色对象，透明像素可能带无意义RGB值，灰阶抗锯齿会产生很多不同像素值。

   重点检查：透明背景、白底小对象、浅色插画、单蓝色线稿、灰阶阴影、黑白主体上的红色标记。背景识别不确定时保留不确定性，不要误删真实白色结构。

4. 画风采用来源信息与视觉复核结合的方式。
   官方明确的系列标签可以作为依据；自动规则提供辅助判断；边界和不确定项通过实际预览复核。
   不要把整个来源统一标成一种风格，也不要用SVG路径数量代替视觉复杂度。

5. 保持原件不变。
   分类、校正和标签更新作为元数据处理，尽量按原文件哈希缓存计算结果，避免重复采集。
   如果以后产生改色或其他派生版本，应单独保存并记录修改，不覆盖原件。

6. 人工网页与Agent使用不同的信息密度。
   网页突出黑白/灰阶/彩色，以及极简/写实等直观筛选。
   Agent接口提供完整结构化字段、筛选依据与不确定状态。
   明确要求彩色或指定画风时，应作为筛选条件；仅表达偏好时，可以作为排序偏好。两种情况需要区分。

五、检索和选材如何避免趋同

1. 科学条件优先。
   对象、必要物种、正常/病理状态、必要视角、使用角色、许可和文件可用性，应先满足。
   不能为了丰富结果，把小鼠换成大鼠，把正常肺换成肺炎图标，或者把局部结构当作完整器官。
   条件不足或信息未知时明确说明，不静默当作匹配。

2. 扩大内部候选集合，再选择前十。
   可从50–100个合格候选开始评估，这只是实现起点，不是固定行业标准。
   明确筛选条件应在候选截断前生效。检查候选集合是否已被单一来源、近似图或变体挤占，避免后续重排无图可选。

3. 在相关性和质量合格的范围内增加多样性。
   同一素材家族通常只占一个结果位置，变体在详情中展开。
   参考MMR或类似轻量方法，减少高度相似作品同时占据前排。
   相似度可以帮助重排，但不能作为自动删除或合并不同科学状态、姿态和结构的依据。
   来源、作者和系列的分布可以作为辅助因素，不设置导致错误素材混入的硬性来源配额。

4. 提供不同使用情境。
   探索阶段：允许展示几组不同但各自协调的画风，帮助确定方案。
   正式绘图阶段：按项目选定的颜色、细节和画风方案检索。
   精确查找阶段：用户明确对象、状态或指定素材时，优先精确满足，不强行轮换。

5. 增加跨项目的受控轮换。
   为每个项目保存选材种子和风格方案。
   在同等合适的候选之间，结合近期真正使用过的素材/家族记录进行适度降权或轮换。
   不默认按下载量或历史使用量越高越优先排序，避免越常用越排前、越排前越常用的循环。
   仅改变末尾几个候选还不够，要检查最终选用的素材是否仍总是同一个。

6. 保证可复现。
   相同目录版本、排序版本、查询、参数、历史记录快照和种子，应得到相同结果。
   新项目可采用新的种子；同一项目修订时维持已选素材稳定。
   分页或换一批时避免反复返回同样的家族。
   不使用每次刷新都不可追踪的随机顺序。

7. 保存小型项目选材记录即可，不需要先建设账号系统。
   记录最终采用的asset ID、family ID、文件哈希、目录版本、项目风格和署名。
   浏览、试下载与最终采用要分开。
   首版可以由skill在项目中保存小型记录并传入必要的排除/偏好参数，记录不包含论文正文等无关内容。

8. 避免新的“小库偏置”。
   精选集和已有5件原生验证素材不能成为检索白名单，也不能因验证过就永久占据前排。
   返回素材的真实验证状态，让Agent查看具体候选再选择。位图、矢量按任务需要选择，不因格式偏好把所有结果压缩到少量SVG。

9. 允许合理复用。
   如果只有一件素材满足医学要求，可以继续使用并说明替代不足。
   不要求每篇都必须使用全新素材，也不把改色后的同一作品当成真正新增的素材多样性。

10. 数据库策略只能减少选材趋同。
    后续skill仍要按每项研究的逻辑安排构图、主视觉和信息关系，不能长期套用同一个布局后仅替换几个图标。
    这一点在后续skill接入阶段落实，当前不恢复训练或盲测。

六、如何验收，避免只增加字段但实际没有改善

保留现有120条中英文检索基准及原有门槛，不删除困难问题，不预绑定固定asset ID来提高通过率。

在此基础上补充：

- 颜色、灰阶、强调色和透明背景等边界样例，实际看图核对分类，并报告错误与不确定项。
- 画风标签的跨来源抽查，避免直接把来源标签当作全库视觉验收。
- 黑白和彩色同一家族的查询，确认预览与下载指向正确变体。
- 明确筛选条件与排序偏好的区别。
- 前十结果的相关性、重复家族占位和近似作品集中情况。
- 同一需求在多个项目种子下的候选覆盖、结果重叠和最终选材重复情况。
- 相同输入的可复现性，以及同项目修订时的稳定性。
- 候选丰富和候选稀缺两种场景。稀缺时不能靠错误素材提高多样性。
- 新策略与原策略的对照，证明多样性改善没有通过明显降低医学相关性获得。

不要只给一个“多样性通过”的布尔值。报告实际观察、剩余缺口和适用范围。参数应根据真实样例调节，而不是为了满足随意设定的数字增加复杂度。
