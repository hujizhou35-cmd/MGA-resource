## 要证明的能力

这套基准检查：Agent 能否找到准确、可读、可分发的医学对象、局部场景，以及为一个明确构图用途找齐必要部件。它不要求图库提供完整论文图、研究设计教学图或统计结果图。

“小鼠和注射器都能找到”与“注射操作图正确”是两种能力。前者可以成为本基准中一个明确命名的部件任务；后者仍需要途径、姿态、接触点和方法依据。新报告必须保留这个区别，不能把部件成绩回填到旧操作题。

本基准在素材收集以后、用户改变验收路线以后建立；作者有本项目既有工作背景，因此不宣称它是采集前盲设的基准。本次起草没有查目录或排名来挑命中项，也没有运行新查询。冻结后不得再按结果改题、换种子、增加兜底搜索或预绑素材 ID。

## 任务、角色与执行接口

JSON 顶层保存 `tasks` 和扁平的 `queries`：

- `task_id`：计分任务的稳定 ID，关联原来的 `legacy_concept_id`。
- `required_roles[].component_id`：该任务必需的素材角色，例如 `mouse`、`syringe`。这是验收角色 ID，**不能直接传成检索核心的医学 `role` 过滤条件**。
- `composition_requirements`：这些对象在新用途下须满足的组合要求。
- `limitations`：本任务不能证明的医学过程或研究结论。
- `skill_generated_elements`：可由绘图工具按真实方法或数据生成的版面元素；它们不计为已检索医学角色。
- 每条子查询包含 `query_id`、`task_id`、`component_id`、`language`、`query`、`filters`、`limit`、`mode`、`seed`、`review_requirements`。执行时仅把实际请求参数传入共享检索核心，不能把预期答案或审阅要求当成元数据标签。

首次冻结前统一确定 `limit=10`、`mode=explore`、`seed=diagnostic-fixed-project`。沿用原固定种子是为了让完全相同的原子请求自然可比较，不是为某件素材择种子；探索与采用历史的多种子检查由已有独立补充验收承担。当前 `filters` 为明确的空对象；不能在执行时临时追加、移除或更改条件。同文字而不同参数的请求仍按 `query_id` 分开保存。

新拆分的子查询以明确对象名称为主。“完整身体”“中性”等构图限制留在 `review_requirements`，实际审阅仍须满足，不能因查询文字简化就放宽。必要的科学对象词与部件词保留，例如 DNA 结合蛋白、细胞培养瓶、针头、枪头；这些决定要找的对象。原样延续的原子任务保持旧查询文字及要求不变。

一个任务在一种语言下通过，必须同时满足：

1. 所有必需角色的子查询均实际运行，完整保存返回顺序、候选家族、命中变体、原件／预览哈希、预览和下载地址、来源与许可。
2. 评审对每个实际返回结果给出 `relevant`、`irrelevant` 或 `uncertain`，并写具体原因。`uncertain` 不计成功；零结果保留零结果。
3. 每个角色至少选中一个来自**该角色自己的前十结果**、且实际符合其要求的精确文件。不能从其他角色查询或历史精选名单补入未返回的素材。
4. 实际判断所选部件满足该任务的 `composition_requirements`，并遵守 `limitations`；记录独立的组合用途判断。仅把各角色布尔值相乘，不能代替这一步。
5. 所选文件可读取，精确许可、署名及来源链可取得；未知物种、视角、状态或功能不能替代任务要求。

一个文件可以承担多个角色，但必须在对应子查询中实际返回，并分别满足每个角色。例如含前后两个人体视图的同一文件可以同时证明两个视角；单一正面人体复制或镜像不能证明背面。

## 复合用途的实际审阅

多角色任务应把所选精确预览放在同一张有界审阅板上，标明对应角色，实际检查可辨认性、透明或白底处理限制、缩小后的细节、标签及画风搭配。它是部件适用性审阅板，不是要新画一个完整医学机制或操作流程。

若中英文选中的文件集合、对应角色与用途完全相同，可以引用同一张审阅板；若换了变体、部件、角色或用途，就不能仅凭家族名复用。无需为成绩强迫不同来源或画风混搭，但必须如实记录不协调或需后续编辑的限制。

静态部件并列时不制造操作关系。需要针尖入体、枪头进管、转子配平、分子结合位点或特定调控箭头的最终作品，必须另查方法及科学依据；不能靠部件检索通过声明这些关系已经验证。

|---|---|---|
| 采血操作 | 人体手臂＋来源支持的采血管 | 穿刺位置、采血动作、采血量或检验结果 |

| 离心分离步骤 | 实验室离心机＋离心管 | 转子兼容与配平、离心完成、上下层成分或参数 |
| 移液操作 | 带枪头微量移液器＋微量离心管 | 实际移液姿势、液体方向、成分或体积 |
| 队列随访流程 | 中性人体对象＋临床评估局部场景 | 已入组、随访次数、失访或检查结果 |
| 随机分组流程 | 中性人群＋口服剂型对象，明确限定口服干预的构图情境 | 随机化、盲法、分配隐藏、药名、安慰剂身份或试验结果 |
| 参与者招募 | 临床人员与成人交谈的局部场景 | 已知情同意、已纳入、符合纳排标准或患有特定疾病 |
| RNA 测序流程 | RNA 分子＋核酸测序仪器 | 可跳过前处理直接测 RNA、具体平台兼容性或完整流程 |
| 表达热图模板 | RNA＋具有结构表现的蛋白对象，作为表达分析的生物背景 | 热图检索通过、实测表达量或两分子的定量／因果关系 |
| 基因网络成品 | DNA 双螺旋＋来源明确的 DNA 结合蛋白结构 | 任意具体网络边、结合位点、激活／抑制或完整机制 |
| 森林图模板 | 有物理形态的计算工作站，作为定量分析的工具对象 | 森林图检索通过、效应量、置信区间、研究数量或荟萃结论 |

这不是把所有流程需求换成器材：分子、人物、局部临床场景和器具分别承担真实用途。组学类包含 RNA、结构蛋白、DNA 及有明确功能依据的 DNA 结合蛋白，同时保留设备对象。森林图工作站任务只覆盖“分析工具对象”，不能对外概括为“已找到森林图”。

问卷调查、人体血压测量、测序仪等原本属于允许对象或局部场景的任务继续保留原要求。例如血压测量仍要求人体、器具与测量动作合理，孤立袖带不满足；问卷素材核查的是给人回答的调查用途，不要求一定画出一个人。

原子对象也不放宽：肝细胞不能用整肝代替，大脑不能用神经网络代替，DNA 不能换成 RNA；来源不能支持的细胞身份、物种、状态或特定功能不得靠外形或标题补造。

## skill 的责任与继续保留的范围待定项

skill 可以按真实研究资料绘制标题、组别标签、时间轴、连接和一般版面几何。热图、森林图等数据图由绘图工具依据真实数据生成。此类工具输出不算库内检索角色，也不提供医学部件缺失时的替代分。

以下边界没有因用户选择组件路线而自动获准：

- 空白森林图／热图模板：不作为本版库内角色，仍不宣布可收录。
- 完整多阶段机制／教学成品：现有待定文件继续隔离，不能因其中含一个器官或分子而计为组件命中。
- 裸框、圆点和箭头素材：不能当医学对象。skill 可绘制一般几何，不等于允许把尚待定的几何素材纳入正式库。

所有候选继续服从已有精确文件范围决定。图上有标签不自动失格，文字属性未知也不等于无字；若标签会妨碍当前用途，应记录限制和选中后工作副本的处理需求，不宣称自动去字已经实现。必需比例尺、方向、结构箭头和科学符号不得随意删改。

旧 120 题、旧查询输出、102/120 正式成绩和六条覆盖失败全部保留。新版本的检索分数只回答本文件定义的组件任务，两种成绩不得互相替换。

- 新基准已冻结，任务和所有请求与冻结版本相同；真实输出与独立逐结果审阅完整。

只有这些条件全部成立，新的组件报告才可单独打开网站阶段。冻结草案、生成候选、写一个脚本或继承旧观察，都不构成通过；当前没有查询结果，也没有可发布声明。
