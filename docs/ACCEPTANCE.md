# 素材收集与验收

首版验收固定使用 [benchmark.json](../data/benchmark.json) 的 60 个真实绘图需求、每项中英文各一条，共 120 条检索。它在正式素材采集前建立。不得为了得到更好数字删除困难题、替换需求或仅凭自身标签命中宣称通过。

## 收集完成的判定

1. 主力来源均有已执行的发现与获取结果，或者有具体的未取得原因、影响范围和补缺决定。配置文件存在、链接存在、仓库 README 宣传数量均不等于取得。
2. 实际发布的每个文件可读取、哈希一致、来源和许可记录齐全；格式检查与预览生成完成。损坏、许可未明确或危险活动内容的图不进入正常分发。
3. 全库去重完成：完全相同的字节只保存一份；作者、来源和许可仍全部保留。相似图、配色或格式变体归为家族，但不能仅凭相似标题合并不同物种或科学状态。
4. 十二类覆盖与独立检索验收通过。记录并展示剩余缺口，不用总文件数代替覆盖。
5. 精选集完成实际预览检查，并包含十二类；原生编辑验证只应用于实际在 Illustrator 中测过的矢量。PNG 可用于最终混合图稿，不要求伪造路径编辑证明。
6. 云端版本包可以恢复；文件地址、哈希及数量与目录一致，更新失败不会让旧目录指向半成品。

上述素材阶段完成后才开始主站建设和部署。当前文件仅定义验收方式，不代表任何门槛已通过。

2026-11-06补充：还须完成[颜色、画风与选材多样性增量验收](INCREMENTAL-PLAN-visual-diversity.md)。原120条查询和数值门槛保持不变；颜色边界、文件/变体对应、明确条件与偏好、跨源风格、多种子与采用历史、确定性分页及新旧策略对照须有真实报告。原有检索检查脚本单独通过不足以宣布新增要求或网站阶段通过。

## 分开记录五类状态

- discovered：只有元数据或来源记录。
- downloaded：已经取得原文件且校验通过。
- machine_checked：可解析、尺寸及真实媒体类型已查，预览已生成。
- visually_reviewed：独立评审实际看过图，记录科学适用、可辨认性和具体缺陷。
- native_verified：在记录的 Illustrator/MCP 环境中完成实际导入、保存重开和局部编辑检查。

这些状态不是单一“通过”布尔值。许可可分发、视觉可用、结构可编辑是不同的判断。位图可以 visually_reviewed 而不具备矢量 native_verified。

## 全量机器检查

- 原始字节不被覆盖；派生预览记录生成工具版本。
- SVG 区分纯矢量、混合图、只嵌位图。嵌位图不是自动淘汰理由，但不能标成可逐路径编辑。
- PNG/WebP 记录原始像素、透明背景及按 300 dpi 换算的尺寸建议。放大预览不增加原始分辨率。
- 预览必须存在、可解码；标签和小字不能因生成预览而被错误判断为原稿缺失。
- 分类允许多标签，物种和疾病状态不从普通形状或来源库名称推断。
- 机器检测不能证明解剖、分子结构或实验关系准确；实际图与来源证据仍须复核。

## 视觉抽查与精选

每个主力来源至少检查十件代表图，不足十件则全查；样本覆盖常见对象、复杂图、矢量/位图、透明/非透明及有文字的图。另建立至少六十件精选审阅集，每类至少五件，允许与来源抽查重叠。

审阅可由人工或独立 Agent 完成。每次记录素材 ID、原文件 SHA-256、看到的预览地址/哈希、来源页、结论、具体问题、推荐使用范围及评审者。不能以生成脚本输出“pass”取代看图。

实际验收至少检查：对象可辨认、物种/视角/病理状态符合来源、人体/动物轮廓完整、文字可读、透明与叠放效果、缩小后质量、组合画布中画风是否协调。发现系列性问题时扩大该批检查并修复或降低适用级别。

## 120 条检索验收

每个查询记录实际前十个结果 ID、排序、预览和下载地址。评审者根据真实预览与来源，给每个结果标 relevant / irrelevant / uncertain；uncertain 不计成功。

查询成功要求：前十项中至少一件可用插画或明确可组合部件满足对象、角色和必要物种条件，并且文件可下载、许可与使用说明可取得。相同素材的多个变体只算一个候选家族。

通过标准：

- 总成功至少 108/120；
- 中文和英文各至少 54/60；
- 每类五个概念中至少四个被实际覆盖；
- 交付下载无损坏或哈希错误；
- 六个单独的负例/格式/物种场景全部给出符合范围的结果。

主基准不靠具体 asset_id 预先绑定结果。检索实现可以使用正常医学词典和同义词，但不能把 benchmark 的“期待命中”直接当真实性标签。复核依据需独立于检索器自产生的分类。

若不通过，按失败原因补：来源、对象、词汇、过滤、画风或真实质量。修复后保留原运行结果并重跑同一版本基准，不能覆盖失败记录。

## 云端验收交付

版本报告应能在线查看，并包含：

- 来源完成状态及真实数量；
- 文件数、逻辑家族数和重复关系；
- 各类及矢量/位图覆盖；
- 120 条查询的原结果与独立评审；
- 精选集和可直接查看的预览；
- 单独的 Illustrator 实测证据；
- 可恢复的 Release 包、完整 manifest 和哈希；
- 尚未解决的访问、许可、科学或画面问题。

所有测试结果必须绑定具体代码提交、目录版本及素材哈希。只有实际运行产生的报告才能写“通过”。
